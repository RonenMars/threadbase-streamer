## Findings

### F1 — A ticketed request that never upgrades spends the ticket and leaves a 24 h socket-less context

*   **Where:** `src/api/middleware/auth.middleware.ts:90-91`, and the missing counterpart to `src/api/routes/ws.routes.ts:63`.
*   **Invariant:** 7 (lifecycle — no orphan without a deadline). Also contradicts NONCE-DESIGN §10's "the residual … for **≤10 s**".
*   **Confidence:** CONFIRMED by trace through both dependencies; not executed.
*   **Severity:** low.

The ticket branch fires on `path === "/ws"` alone. It does not require `Upgrade: websocket` and does not require `GET`.

Traced path:

1.  `GET /ws` (or `POST /ws`) with a valid `X-TB-Ticket` and no `Upgrade` header → `registry.consumeTicket()` deletes the ticket **and** calls `markUsed()`, which flips the context out of provisional and sets `expiresAt = now + WS_CONTEXT_TTL_MS` (24 h) — `context.ts:544-556`, `markUsed` at `context.ts:279`.
2.  `authenticateContext` succeeds, the capability check passes, `c.set("e2eeContext", …)`, `await next()`.
3.  `refuseUnsealedIfPinned` returns `null` because a context is present → `next()`.
4.  `@hono/node-ws`'s helper runs `if (c.req.header("upgrade")?.toLowerCase() !== "websocket") return;`, and hono's `defineWebSocketHelper` then does `await next()` → 404. `onOpen` never runs, so `addClient` never runs.
5.  Nothing destroys the context. The two orphan-closers this PR added are the capability refusal (`auth.middleware.ts:161`) and the falsy-`ws.raw` case (`ws.routes.ts:63`); neither is on this path, and the 10 s first-frame deadline is armed inside `WSHub.addClient`, which was never reached.

Failure scenario: `curl -H "X-TB-Ticket: <t>" http://streamer/ws` answers 404, the ticket is spent, and one non-provisional WS context with live traffic keys sits in the registry for 24 h with no socket and no clock, holding a slot against `MAX_WS_CONTEXTS_PER_DEVICE = 4`. Four such requests occupy the device's whole live-context budget until eviction reclaims them on a later `/open`. A proxy that strips `Upgrade`, or a client bug, reaches the same state without an attacker.

Why it is low and not high: it needs a valid ticket (a completed Noise handshake against the device's static key, or theft of one), it yields no plaintext, no key material and no hub membership, and it is the same residual shape §13 already accepts and documents for a mismatched-credential upgrade ("one orphaned socket context per mismatched upgrade, living out its lifetime").

Why it is still worth fixing: here the orphan is produced by the **success** path rather than by a refusal; the sibling falsy-`ws.raw` orphan was closed in this very PR with the comment "Every other path that abandons a consumed context destroys it; this one was the exception" — this is the one remaining exception; and no test covers it (nothing in the 1,965 added test lines exercises `/ws` without `Upgrade`).

Fix shape: spend the ticket only on a request that can actually become a socket — gate the branch on `method === "GET"` and on hono's own upgrade predicate, mirrored exactly. See `tracks/W/CODEX-BRIEF-PR748-F1.md`.

## Invariants checked and found to hold

1.  **Nonces / counters.** Every seal goes through `WSHub.sendTo` → `context.sendState(CHANNEL_WS).seal()`; the counter is owned by the W1a `RecordState`, one context per socket, never resumed (a reconnect needs a fresh `POST /api/e2ee/open`; tickets are minted only for `kind === "ws"`, `e2ee.routes.ts:405`). Broadcast memoises the **plaintext** only and seals N times. No randomness anywhere on the nonce path.
2.  **Strict counters, code separation.** `receive()` reports the record layer's own code (`sealCode`) — gap/repeat → `E2EE_SEQUENCE_VIOLATION`, bad tag → `E2EE_SEAL_FAILED`. The send path coerces a hypothetical `E2EE_SEQUENCE_VIOLATION` to `E2EE_SEAL_FAILED` (`sendCode`) while logging the original under `reported`. The two never collapse.
3.  **Ticket.** Header-only, no `?ticket=` fallback anywhere in the diff; check-and-consume is a synchronous map read+delete with no `await` above it; failure is terminal (401, no fall-through to bearer or `?key=`); never logged, even reduced.
4.  **`authenticateContext`.** Pure verdict; no destroy, no log, no throw — `get()`, the `Object.hasOwn` and the value reads, and `authenticate()` are all inside `try` blocks, and the only work outside is `parseCapabilities`, which is itself `try`-wrapped. Missing row or missing `revoked_at` column ⇒ `device-revoked`; credential naming no device ⇒ `credential-mismatch`; null-or-throwing store ⇒ `no-device-store` → 503, not 403. `principal.deviceId` is `context.deviceId` by construction.
5.  **No plaintext escape.** `broadcast`, `broadcastToClients` and `unicast` all route through `sendTo`; `git grep '\.send('` over `src/*.ts` finds no direct WebSocket send outside `ws-hub.ts`. `everSealed` is set at attach and guards both `sendTo` and `receive`. `handleWsOpen`'s synchronous `session_list`/`cache_ready` go through `wsHub.unicast`, so they are sealed. The bare catch is narrowed to `JSON.parse`, with `receive()` outside both catches.
6.  **Prototype pollution.** `own()` on `req.headers["content-length"]` and on the `firstFrameMs` option; ticket and authorization read through `c.req.header()`; `keepOwnUpgradeHeaders` null-prototypes the raw headers before `@hono/node-ws`'s `for…in` copy, installed with `prependListener` so it runs first.
7.  **Lifecycle.** Close destroys only its own context (`destroyOwned`), never the device's REST context; revocation, single delete, `?force=1` delete and bulk delete all call `cutLiveContexts` (the bulk path correctly filters `list()`'s `DeviceView.revokedAt`, matching `toDeviceView`); the maintenance pass reaps sockets whose context is no longer the registry's. **Except F1.**
8.  **Bounds before allocation.** `wss.options.maxPayload = 64 KiB` on the exact `WebSocketServer` `createNodeWebSocket` returns; `ws` reads `this.options.maxPayload` per upgrade at `websocket-server.js:435` (`ws.setSocket`), so the assignment binds every subsequent socket and the refusal happens in the receiver before assembly.
9.  **Released clients.** The legacy `?key=`/bearer path is untouched when no ticket header is present; pinned devices still go through W1a's `refuseUnsealedIfPinned` (426); no response field removed or renamed; `protocol.ts` is not in the diff, so the four frozen codes are unchanged. The 64 KiB c2s ceiling is safe for released clients — `handleWsMessage` handles only `register`, `subscribe_session`, `unsubscribe_session` and `hold_session`, all sub-kilobyte.
10. **Test honesty.** Spot-checked six of the most security-relevant added tests: the concurrent ticket race (602), the spent-ticket-to-bearer downgrade (632), the first-frame deadline with its long-deadline positive control (1129/1147), the inherited `X-TB-Ticket` case (1353, with `ticketCount === 1` proving non-consumption), the frame ceiling (1827, with an under-the-ceiling control), and the plaintext-send-path detach (1889, which settles before asserting no leak and checks the project path never appears on the wire). All discriminate. The harness is real end to end — real `http.Server`, real Hono app and auth middleware, real `@hono/node-ws` upgrade, real `ws` sockets, real SQLite device rows, real `/api/e2ee/open` handshake driven client-side — and the ciphertext capture has an explicit legacy-socket negative control at 518.
