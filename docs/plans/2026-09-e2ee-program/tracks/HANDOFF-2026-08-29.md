## 2. Rules that bind whoever continues

- **Never push to `main`; one PR at a time per repo; rebase onto latest `main`, squash-merge on green CI.** Streamer releases are semantic-release tags; downstream work keys off **tags, never merge commits**.
- **Commit approval:** show the staged diff (`git diff --staged`) and the verbatim message to the user and wait for an explicit yes. Conventional-commit titles; body one sentence per line; **no AI attribution anywhere** (commit, PR, issue).
- **Worktrees only:** streamer work in `tb-streamer/.worktrees/<type>/<slug>` (symlink `node_modules`), mobile work in `../tb-mobile-worktrees/<slug>` (own `npm ci`). Root checkouts are read-only. Cite code from `origin/main` (`git show origin/main:<path>`), never from a checkout.
- **Absolute binaries** on this machine: `/opt/homebrew/bin/git`, `/opt/homebrew/bin/gh`, Node `$HOME/.nvm/versions/node/v24.15.0/bin/node`. Biome pinned **2.5.10** in the streamer (a symlinked 2.5.3 exists — run the pinned one via `npx @biomejs/biome@2.5.10`).
- **Crypto guardrails** (CLAUDE.md §3): nonces are `direction(4)‖counter(8)`, never random; WS counters strictly monotonic, no window; REST uses an RFC-6479 sliding window (1024 wide); unseal runs before `authMiddleware`; reject unknown `ctxId` before any allocation and bound body/header size **before** base64 decode (D-9); fail closed at every trust boundary (absent ≠ invalid ≠ success; no store / unreadable store = refusal); `--no-e2ee` is a `serve` flag only; never break released clients; **no in-place rekey** — a new key is a new context (user ruling B3).
- **Verification bar** (CLAUDE.md §4): real objects on the production path; a positive control; a negative control; **one mutation per safeguard, applied, seen red, reverted**, reported as `<file>::<test>` + verbatim assertion. Driver rules: apply in `try`, revert in `finally`, verify restoration by **sha256 against pristine copies** (`git diff --quiet` is blind to untracked files), a module that fails to import is `BROKEN — did not run`, never a pass; a mutation that provably cannot change behaviour is struck, not counted. The campaign is **re-run on every refreeze and after every rebase**, never carried forward.
- **Acceptance of crypto changes is an isolated adversary**: a fresh agent with the spec and the built artefact, in its own worktree at the exact commit, no implementer context, briefed from `tracks/W/ADVERSARY-BRIEF.md` (+ `-ADDITIONS.md`) and the track's own row table.
- **Evidence hygiene:** scrub API keys, pair tokens, `spk`, tickets, device tokens, tunnel hostnames before anything leaves the scratchpad; taps log argv. Rigs run under a scratch `HOME` + `THREADBASE_CONFIG_DIR`, never the real `~/.threadbase`; shut down every streamer/simulator/tunnel you started.
- **Frozen at v1.71.0** (do not rename): codes `E2EE_CTX_UNKNOWN`, `E2EE_DEVICE_REVOKED`, `E2EE_SEQUENCE_VIOLATION`, `E2EE_SEAL_FAILED`; helper `refuseUnsealedIfPinned`; `/open` = psk-less `Noise_IK_25519_ChaChaPoly_SHA256`, prologue `"threadbase-e2ee/1 open"`.
- **Stop and ask the user** (CLAUDE.md §6) on: a private key/token in any log or PR; two writers on one file; a plaintext frame on a sealed channel; anything that would force-update released apps; a `dilemmas.md` dilemma turning load-bearing.
- **Two things only the user decides:** the stage-2 flag default flip (`e2ee` `default: true` in `src/feature-flags.ts` — its own one-line PR, opened by R, merged only on the user's explicit go), and the D-8 collision (R2 escalation, options in `tracks/R/prompt.md`).

## 4. Frozen seam between W1b and X-server (must match on both sides)

```ts
export type DevicePrincipal = Principal & { kind: "device"; deviceId: string };
export type E2eeContextAuth =
  | { ok: true; principal: DevicePrincipal }
  | { ok: false; reason: "device-revoked" | "credential-mismatch" | "no-device-store" };
export function authenticateContext(args: {
  context: E2eeContext;                       // already resolved by the caller
  devicesRepo: DeviceLookup | null | undefined;
  presented: string | undefined;              // credential beside the context; undefined = none = ordinary success path
}): E2eeContextAuth;
```

Semantics: pure — never destroys, never logs, never throws for store conditions; fresh `devicesRepo.get(context.deviceId)`; `device-revoked` covers a set `revoked_at` and a **missing row**; `no-device-store` covers a null or unreadable store (`get()` throws); `credential-mismatch` covers a credential naming another device **or no device** (the shared API key); read `revoked_at` with `Object.hasOwn`; invariant `principal.deviceId === context.deviceId` (principal from the context's row, never from the credential).
Callers apply the effect: WS may destroy on either reason (ticket already spent); REST seals the refusal with the live context first and destroys only on `device-revoked`. Status mapping (both channels): `device-revoked` → 403, `credential-mismatch` → 401, `no-device-store` → 503 `STORE_UNAVAILABLE` (a store fault is never reported as a revocation). `DevicePrincipal` is an intersection type — `Extract<Principal, {kind:"device"}>` yields `never`.
Any outcome REST needs that this set lacks is a signature change and must land **before** W1b merges.
