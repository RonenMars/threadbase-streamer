## 4. Frozen seam between W1b and X-server

This interface remains the merge precondition:

```ts
export type DevicePrincipal = Principal & { kind: "device"; deviceId: string };
export type E2eeContextAuth =
  | { ok: true; principal: DevicePrincipal }
  | { ok: false; reason: "device-revoked" | "credential-mismatch" | "no-device-store" };
export function authenticateContext(args: {
  context: E2eeContext;
  devicesRepo: DeviceLookup | null | undefined;
  presented: string | undefined;
}): E2eeContextAuth;
```

Semantics:

- pure: never destroys, never logs, never throws for store conditions;
- fresh lookup by `context.deviceId`;
- missing row or set `revoked_at` = `device-revoked`;
- null/unreadable store, including a throwing `revoked_at` accessor = `no-device-store`;
- credential naming another device or no device = `credential-mismatch`;
- successful principal ID comes from `context.deviceId`, not the returned row or credential;
- callers apply effects: WS may destroy after a consumed-ticket refusal; REST seals first and destroys only on `device-revoked`.

Status mapping remains 403 / 401 / 503 `STORE_UNAVAILABLE` for the three refusal arms.
Any signature or semantic change must land before W1b releases and be rechecked by X-server.
